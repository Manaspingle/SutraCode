SYSTEM ARCHITECTURE

How SutraTrace Eliminates AI Hallucinations

Traditional LLMs guess based on generic training weights. SutraTrace anchors every claim in verbatim passages retrieved from your uploaded technical manuals.

STEP 1
Document Extraction

Uploaded PDF and TXT programming guides are parsed using PyMuPDF. The engine preserves structural metadata including page numbers and source titles, discarding empty pages.

PyMuPDF (fitz) • Page Preservation
STEP 2
Sliding Window Chunking

Continuous documentation text is split into semantic chunks of 700–1,000 characters with a 150-character overlap, breaking cleanly on sentence and paragraph boundaries.

Chunk Size: 850 chars • Overlap: 150
STEP 3
Vector Embedding Store

Passages are vectorized into 384-dimensional dense vectors using all-MiniLM-L6-v2 and persisted in a local ChromaDB HNSW index tagged with the user's isolated namespace.

ChromaDB • Cosine Space • MiniLM
STEP 4
Multi-Modal Query Expansion

When you submit code, SutraTrace synthesizes the programming language, reported error message, expected behavior, and code signature into a high-signal search query.

Query: [Lang] + [Problem] + [Trace]
STEP 5
Gemini Grounded Reasoning

Top retrieved passages pass through a relevance threshold filter. Gemini 3.1 is instructed to treat user code and retrieved passages as untrusted content, preventing prompt injection attacks.

Google Gemini 3.1 • Temp: 0.1
STEP 6
Verifiable Output & Diffs

Gemini produces structured JSON separating observations, root causes, minimal line diffs, and exact citations. Missing evidence is explicitly acknowledged. Untrusted code is never executed.

Structured JSON • Zero Execution Risk
